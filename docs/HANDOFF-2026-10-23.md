## 3. AI price sync (WIP commit)

**What the user asked for**
- Fetch and update model prices automatically from the pricing pages of Codex Everywhere (https://docs.codex-everywhere.com/models/), Anthropic and OpenAI.
- A "Check now" button and an optional automatic update every ~10 h.
- Choosing per model which page its price comes from.
- Providers only. It must be accurate.
- No provider has a pricing API, so the pages are read by an AI run through one of OUR pools at OUR cost, grouped as a "pricing fetch AI run".

**How it is built**

| File | Role |
|---|---|
| `prisma/migrations/20261023180000_price_sync` | Tables `PriceSync` (per-provider config) and `PriceSyncRun` (history, proposals, applied changes). |
| `src/server/pricing/price-sync/text.ts` | Fetches a page with the SSRF guard, converts HTML to text, extracts numbers, and checks names. |
| `src/server/pricing/price-sync/ai.ts` | The internal customer `pricing-fetch@system.internal` ("Pricing fetch AI"), with multiplier 0, so price is 0 but cost is recorded. Its API key sits in pool `priceSyncPool`. Calls `handle()` in-process via `/v1/chat/completions`. |
| `src/server/pricing/price-sync/engine.ts` | Config and defaults per preset, the prompt, the zod contract for the AI's JSON, `buildProposals` (verification and statuses), `runPriceSync`, `applyPriceSyncRun`, `runDuePriceSyncs`. |
| `src/server/admin/price-sync-{actions,queries}.ts` | Server actions (save config, per-model page or exclude, run, apply) and the panel data, including the AI cost from RequestLog. |
| `src/components/admin/providers/price-sync-card.tsx` | The "Price sync" card on the provider page. |
| `src/lib/settings.ts` | `priceSyncPool` (default `coding`) and `priceSyncModel` (default `claude-sonnet-5`). |
| `src/server/maintenance.ts` | Job `priceSync`, checked hourly, runs providers whose `auto` is on and whose interval has passed. Official-basis providers run first. |
| `src/server/billing/auto-recharge.ts` | No balance emails to `@system.internal` users. |
| `src/app/admin/status/page.tsx` | Shows the new job. |

**Rules**
- Every price must be written on the page it came from; model and pool names must be on the page too.
- Promotional prices are never used; the regular list price is kept (the user's rule).
- A price the page doesn't give is never cleared.
- The 1h cache write applies to Anthropic only.
- For image models: `input` and `cached_input` come from the Text row, `output` from the Image row (matches our data).
- For a pool image model with a flat per-image price, only `imageCost` is set; token costs stay as they are.
- Statuses:
  - `update`: clean and within `maxAutoChangePct` (default 50). An automatic run applies these.
  - `review`: an admin decides.
  - `same`, `missing`, `excluded`.

**Bases**
- `official`: our cost = the page price. When the provider preset equals the model's vendor, the model's `official*` list prices are updated too, then `recomputeModelPrices`.
- `pool`: our cost = the model's official price × the pool's % from the page.
  - Cache writes: 0 if the page says the pool doesn't charge them; official × % if it does.
  - 1h cost: comes from the official vendor route.

**Default pages**
- openai: `https://platform.openai.com/docs/pricing.md`
- anthropic: `https://platform.claude.com/docs/en/about-claude/pricing.md`
- codex-everywhere: `https://docs.codex-everywhere.com/models/`, pool name taken from the provider name ("Codex Pro Pool", "Claude via Kiro").

**Live validation already done.** The prompt and `buildProposals` were run against the real pages with a snapshot of the prod routes, through prod with claude-sonnet-5:
- All 4 providers mapped every model correctly and all current prices matched, so the result was "same".
- CE pools read correctly: 5% with no cache writes and $0.015 images for Codex Pro Pool; 8% with cache writes charged for Kiro.
- gpt-5.6-sol's promo was detected and the list price kept.
- Planted wrong prices were caught as `update`.
- Each run costs about 3–15K tokens, $0.001–0.01, and takes 12–17 s.

## 6. Test keys and live checks

- Prefer API keys the user creates in the portal.
- Without them, mint a key by SQL:
  1. Generate `sk-pp-` + 40 base62 characters.
  2. `INSERT INTO provider_proxy."ApiKey"` with `keyHash` = sha256 hex of the key, a `groupId`, and a name ending in "(temporary)".
  3. Delete it afterwards through a migration.
- The gateway caches keys and providers for 30 s, so an SQL change takes up to 30 s to show (a first call may 503).
- Upstream keys can be added by SQL as `secretEncrypted = 'plain:<key>'`. They work immediately, and the next upkeep pass encrypts them and sets the hint (PR #35).

## 7. Gotchas

- **Supabase MCP `execute_sql` never runs DELETE:** it waits for a confirmation that doesn't arrive. Use id-scoped migrations for deletes. INSERT and UPDATE work.
- **gcloud credentials in the cloud session expired.** Deploys go through merges into `main`.
- **Flaky tests that fail on `main` too:** the chaos multipart test passes when run alone, and the audit-regressions brotli test times out.
- **Next.js 16:** read `node_modules/next/dist/docs/` before changing framework APIs (`AGENTS.md`).
- **Commit trailers:** commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Don't add model names elsewhere.
